# 会話の文脈と訂正（2026-09-14）

追加の有料AI APIは使用しない。自由文の意図を日時解析より先に判定し、登録確認と本人所有の予約照合を経て既存の受付処理へ渡す。

- 「12日をキャンセル。11日はキャンセルしない」では、取消対象と残す対象を分けて照合する。本人の同日に複数予約がある場合は選択を求める。
- 取消は対象の日時・店舗・直前取消条件を提示した後、ボタンまたは確認中の「はい、お願いします」で申請する。「やめる」「戻る」後の古い確認ボタンでは実行しない。
- 引用だけでは引用先と予約の対応を推測しない。本人の予約候補から対象を選んでもらう。
- 変更開始時は元の店舗を引き継ぐ。変更中に貼り付けた早見表日時は新規の一括受付に入れず、変更対象を保持した確認画面へ進む。変更には日時を1つだけ指定する。
- 変更入力の中止は元の予約を取り消さない。送信済みの未承認変更を取り消す場合は、変更リクエストの取消確認へ進む。承認済みの場合は自動で元へ戻さない。
- 同日時・同店舗の再送は本人の既存予約と照合し、追加受付・追加通知を抑止する。Webhookの利用者単位の排他処理と併用する。
- 「やっぱり12時」など確認段階の言い直しも受付前に反映する。会話期限後は変更元の予約を選んでもらい、新しい希望日を引き継ぐ。
- 日付直後の曜日表記は補足と扱い、月内の同曜日や別日へ展開しない。入力済み日付は一つ前の店舗選択へ戻っても保持する。

## 検証と制約

`tests/test_conversation.py` は実際の困り方を匿名のテストデータで再現する。SQLiteおよびローカルFirestore emulatorで既存回帰テストと併せて実行する。実LINEへのテスト送信は行わない。

自由文すべての意味を理解する仕組みではない。曖昧な対象や引用は選択・確認で補う。キャンセル待ちの自由文登録は担当者への相談を案内し、Botが登録したとは回答しない。Calendarの変更・取消反映は引き続きスタッフが行う。セッション・操作トークンは期限付きで、過去の会話全文やスクリーンショットは保存しない。

本番配備では既存のFirestore設定を維持し、無トラフィックのリビジョンを認証・ヘルス・署名付き空Webhookで確認してから配信を切り替える。DBスキーマ変更はない。
