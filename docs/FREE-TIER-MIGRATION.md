# 固定DB費用の撤廃（2026-09-14）

ユーザーの「無料を基本、発生しても最小限」という指示を優先します。先に導入したCloud SQLはFirestoreへのデータ移行・検証後に撤去します。

## 構成

- Firestore Standard / Native、東京、`(default)`。API応答の`freeTier: true`を確認済み。
- Cloud SQLのような常時稼働インスタンス料金なし。保存・読み書きの無料枠内での運用を基本とする。無料枠超過やその他サービスの利用分まで無条件で無料になる構成ではない。
- Firestoreの有料PITR・管理バックアップ・TTLを使わない。削除保護は有効。
- LINEイベントの処理時に通知Outboxを送る。失敗分の定期再試行は5分ごとに抑え、空の確認を減らす。キャンセル待ちは従来の15分ごと。
- 予約と通知を1トランザクションで保存。イベント・利用者・通知の排他とLINE retry keyを維持。
- SQLite、PostgreSQLのコードはローカル検証・移行互換用。本番の設定はFirestoreを明示する。

## 移行手順

1. Firestore用コードを0%トラフィックのリビジョンで接続確認する。
2. Schedulerを一時停止。SQL接続を1本確保し、旧アプリのDBパスワードを変更して他のSQL接続を終了する。旧アプリが新規書込できない状態にする。
3. SQLの全7テーブルを一貫したスナップショットとしてローカルJSONへ保存する。資格情報と個人情報をGitやログへ出さない。
4. 空のFirestoreへインポートする。旧処理の未完了リースを解放し、通知retry keyと受付IDは保持する。全レコードの正規化SHA-256と件数を照合する。
5. Firestore版へ100%切り替え、認証・ヘルス・署名付き空Webhookを検証してSchedulerを再開する。
6. SQLのバックアップとインスタンスを削除する。停止だけではディスク等の料金が残るため、削除完了とSQL参照の除去まで確認する。

旧SQLへのロールバックはできません。Firestore版の修正版を配備し、データ修復が必要なら退避JSONと現行Firestoreを照合します。

## 費用の範囲

[Firestore公式料金](https://cloud.google.com/firestore/pricing)の無料枠を利用します。Cloud RunやScheduler等の無料枠は請求先アカウントの他の利用状況にも依存します。LINE側のメッセージ契約、すでに発生したCloud SQL利用料、ビルドや保存容量の超過分は別です。ゼロ円の上限保証はしていません。
