## 継続運用・残る制約

- 単一ゾーンの小規模DB。利用増加時の増強と、別環境へのバックアップ復元試験が必要。
- 旧SQLiteのすでに失われた履歴は回復できない。回収範囲は移行記録のとおり。
- Calendarの本人ID関連付け、スタッフ承認・取消反映は引き続き運用作業。
- キャンセル待ちシートの状態列を処理中に並べ替えない。DB回答状態が正本。
- 2028年以降の祝日、監視通知先、個人情報の保持期間を継続管理する。

本番移行の順序とロールバック制約は[ROLLOUT.md](ROLLOUT.md)を参照。

## 実施済み検証

- Python 3.12.12 / SQLite：72成功、PostgreSQL専用移行テスト1件は対象外。
- ローカル専用PostgreSQL 16.15：73成功（移行の成功、二重インポート拒否、通知を送らないことを含む）。
- requirements.lockのハッシュ付きインストール、pip check、git diff --check、deploy.sh構文検査。
- 本番LINEへテスト通知は送信していない。LinuxコンテナはCloud Buildでビルド済み。署名付き空イベントと認証付き読み取りAPIで確認。
- Cloud Buildの2つの既存自動配備トリガーはいずれも `^main$` に限定されることを読み取り確認。移行時に両方を一時停止。移行後は1つだけを無トラフィック配備用に有効化する。
