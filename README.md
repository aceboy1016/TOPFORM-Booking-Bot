# TOPFORM Booking Bot

TOPFORMのLINE仮予約受付システム。FastAPI / Python 3.12 / LINE Messaging API / Google Calendar・Sheetsを使用します。

## 予約ルール

- Botは仮予約を受け付け、スタッフがカレンダーへ登録後に承認します。仮予約では枠を確保しません。
- 2か月先の同日まで（月末に同日がなければその月の末日）。開始は30分刻み、1枠60分。
- 店舗間の移動は60分。平日8–23時、土日祝9–20時。終了時刻まで営業時間内である必要があります。
- 店舗○×・個室A/Bは希望です。登録されていない利用者の予約操作は拒否します。
- 12時間以内の変更は取消申請（1回分消化）、3時間以内は直前取消申請です。

## 開発

```sh
python3.12 -m venv venv
venv/bin/pip install --require-hashes -r requirements.lock
venv/bin/pip install -r requirements-dev.txt
venv/bin/python -m pytest -q
```

テストはLINE・Googleへの送信を行いません。実動作には`.env.example`にある環境変数を設定してください。資格情報JSONを作業ツリーへ置かないでください。

```sh
venv/bin/python -m uvicorn main:app --reload --port 8002
```

SQLiteはローカル開発専用です。本番Cloud Runは`DATABASE_BACKEND=firestore`、`FIRESTORE_PROJECT`を指定し、無料枠対象の `(default)` DBを使用します。Cloud SQLの常時課金は不要です。無料枠超過時の従量課金はあるため、利用量を確認してください。

## トークからの仮予約

「明後日恵比寿で空いてる？」から空き時間カードを表示します。「金曜日は？」では店舗を引き継ぎ、「9/18 半蔵門13:00」のように日時・店舗をまとめて変更できます。空きがない場合も日付と店舗を保持し、次の「19:30」で内容確認へ進めます。

時間はカードをタップしても文字で入力しても選べます。10件を超える候補は「次の時間を見る」で表示し、最後に「仮予約を申し込む」で受付します。スタッフ確認までは予約確定・枠確保ではありません。時間カードは本人に紐付き、以前の一覧でも最新の空きを確認して再利用できます。変更中は変更先として扱い、申込み確認は選び直すたびに更新して二重受付を防ぎます。外部AIサービスは追加していません。

「今って何回目？」「今月の利用回数を教えて」には、今月の日付の予約件数（仮予約を区別、取消済みを除外）、選択中の予約の予定順を答えます。途中の予約・変更内容は保持します。変更申請は予定回数では変更元と二重に数えません。時間カード・ページ送りは発行から7日間、申込み確認は30分間有効です。


## 会話を続けながら探す

「午前中ならいつでも」「19時以降」「今週どこか」「一番早く取れるのは？」に対応します。「ほかの時間は？」「もう少し遅め」「さっきの時間に戻して」でも、店舗や検索条件を引き継いで最新の空きを表示します。「恵比寿がダメなら半蔵門で」は店舗の優先順を指定できます。満席の日は、別店舗や近い日の候補を提示します。候補の提示では予約は作成しません。

確認カードから日時・店舗を選び直せます。「これ、もう確定してる？」「この予約を入れたら今月何回？」には、途中の操作を保ったまま回答します。「変更やっぱりやめる。元のままで」は変更操作を中止し、変更元を案内します。判別できない入力は操作候補を提示します。

キャンセル待ち・空き通知は廃止しました。古いボタンからの受付も行いません。「石原さんに相談したい」は、内容確認後にスタッフへ通知して元の予約操作に戻れます。追加の外部AI APIは使用しません。


## 管理者LINEで確定

予約が届くと、現在の管理者LINEに名前・日時・店舗と「✅ 確定する」「今回は見送る」のカードが届きます。カレンダーを手動登録してから「確定する」を押すと、登録内容を自動照合し、お客様へ緑色の確定カードを送信します。「今回は見送る」は確認後に結果を通知します。

「承認待ち」で、以前の通知を含む未処理予約を呼び出せます。カレンダーの書き込みは行わず、管理者本人だけが操作できます。


## 日程調整の自然なやり取り

「27日16時 → 28日15時半に変更」「7/22の予約を29日16時半蔵門へ」のように変更元・変更先を分けて処理します。変更の文章に早見表の予約希望を添えても新規の複数予約にはしません。「来週土曜1000の予定を変更、日曜の候補は？」は変更元の週を引き継ぎます。

「17日、時間の変更はできますか？」では同日の候補を表示し、「半蔵門15時お願いします」で店舗と時刻を受け取ります。「730」「１０００」などの時刻も読めますが、通常の営業時間・30分刻み・60分枠を適用します。両店舗の候補に対して時刻だけ返した場合、その時刻の表示候補が1店舗1日だけなら引き継ぎ、複数なら店舗を確認します。

「変更先は未定」「新しい日程はまた連絡します」には、元の予約を残すか、先に取消確認へ進むかのカードを表示します。未定というだけで元の予約を取り消しません。取消は従来の本人確認・期限条件・最終確認を通し、Calendarの反映はスタッフが行います。元の予約を残した場合は通常のセッション内で日程選びを再開できます。セッション終了後は元の予約日時を添えて再度変更を依頼できます。


個室A/Bは限定ではなく希望です。恵比寿の時間カードは希望個室の枠と、希望個室が埋まっていて別個室なら空いている枠を区別します。別個室のボタンはその部屋の内容確認へ進み、最終受付前に再検証します。顧客マスタの希望は書き換えません。消化・残回数の台帳は管理せず、予約日が今月の予約件数と予定の順番を表示します。
